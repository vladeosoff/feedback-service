# Feedback Backend API

Backend-сервис для лендинг-презентации с формой обратной связи, AI-интеграцией и файловой системой хранения.

## 1. Как запустить проект

### Установка и запуск
```bash
# 1. Клонировать репозиторий и перейти в папку
git clone <your-repo-url>
cd feedback-backend

# 2. Установить зависимости
npm install

# 3. Создать файл .env на основе .env.example и заполнить его (особенно OPENAI_API_KEY и SMTP данные)
cp .env.example .env

# 4. Запустить в режиме разработки
npm run dev

# Или собрать и запустить продакшн-билд
npm run build
npm start

## 2. Стек технологий

Backend: Node.js, TypeScript, Express.js
Валидация: Zod
Логирование: Winston (в файл и консоль)
AI: OpenAI API ()
Email: Nodemailer (Ethereal для теста)
Документация: Swagger (swagger-jsdoc + swagger-ui-express)

## 3. Архитектура

### Использована слоистая архитектура:

Controllers: обработка HTTP-запросов/ответов и валидация.
Services: бизнес-логика (AI, Email, Rate Limiting, Metrics).
Routes: маппинг URL на контроллеры.
Middlewares: глобальная обработка ошибок, валидация схем.
Utils: утилиты для работы с файловой системой (JSON-хранилище).

Почему такой выбор: TypeScript обеспечивает строгую типизацию, Express.js — легковесность и скорость разработки. Файловое хранилище выбрано в соответствии с ТЗ для демонстрации работы с FS без усложнения инфраструктуры БД.

## 4. Реализация API

POST /api/contact — прием формы. Валидирует имя, телефон, email, комментарий. Возвращает 200 (OK), 400 (Validation Error), 429 (Rate Limit), 500 (Server Error).
GET /api/health — проверка статуса сервиса.
GET /api/metrics — статистика обращений и тональностей.

## 5. AI-интеграция

Инструмент: OpenAI API ().
Задача: Анализ тональности комментария (positive/neutral/negative) и генерация краткого вежливого ответа.
Fallback: Если API-ключ не указан или OpenAI недоступен, сервис не падает, а возвращает стандартный нейтральный ответ и помечает тональность как neutral. Это гарантирует доступность формы 24/7.

## 7. Хранение данных

Логи: data/logs/combined.log и data/logs/error.log (через Winston).
Rate limiting: data/rate-limits.json (хранит IP, количество запросов и время сброса).
Статистика: data/metrics.json (хранит общее число запросов, успешные/неуспешные и агрегацию по тональностям).
